# TinyStories: третий опыт, с большим охватом весов

Готовая языковая модель [roneneldan/TinyStories-1M](https://huggingface.co/roneneldan/TinyStories-1M), обученная авторами на коротких историях. Фактически **3 745 984 независимых параметра**, включая embeddings. В восьми трансформерных блоках — 398 336 параметров. Название 1M не используется как фактическое общее число весов.

Архитектура GPT-Neo: 8 слоёв, hidden 64, 16 голов, FFN 256, GELU, обучаемые позиции, чередование global/local attention. Входной embedding/readout связан. Оригинальный checkpoint 48 578 813 байт содержит также фиксированные маски и не меняется; конфигурация, revision и SHA-256 в sources.json.

Стадия правок охватывает целые attention/FFN проекции всех восьми блоков, от 32 768 до 197 632 изменяемых значений на кандидата. Это существенно больше предыдущих 16/52 скаляров. Формулы всё равно имеют несколько явных коэффициентов: количество затронутых весов не приравнивается к числу независимо сконструированных вычислений или к новому знанию модели.

## Чистое воспроизведение

Скопируйте собственные `.py`, `tests`, sources.json, requirements.txt в новую папку; не переносите старые protocol/results/checkpoints/freeze:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python fetch_sources.py
.venv/bin/python experiment.py baseline
.venv/bin/python diagnose.py
.venv/bin/python propose_edits.py
.venv/bin/python experiment.py finalize
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python make_paper_artifacts.py
```

В исходном локальном запуске использован Python 3.12 venv с read-only существующим torch и совместимыми пакетами локального кэша, подключёнными через `.pth` внутри этого venv. Системные установки не менялись. На другой машине достаточно обычной установки requirements.txt.

Один явно заданный кандидат: `python experiment.py edit --spec hypotheses/edit_01.json`. Бюджет общий для ручных запусков и propose_edits.py; не смешивайте их. Повторный `python experiment.py report` только пересчитывает сравнение сохранённых финальных прогнозов и не разрешает возобновлять подбор.

## Что измеряется

Использованы восемь новых, заранее выбранных разделов BLiMP: anaphor_number_agreement, determiner_noun_agreement_2, regular_plural_subject_verb_agreement_2, irregular_plural_subject_verb_agreement_2, irregular_past_participle_verbs, distractor_agreement_relational_noun, passive_1, intransitive. Они не совпадают с восемью разделами прежнего опыта Glimmer. Абсолютные проценты разных поднаборов не считаются рейтингом моделей.

На раздел выделены 128 diagnostic и 256 validation-примеров, остальные идут в закрытый test. Точные дубликаты и повторения предложений исключаются до измерений; исходные хеши и seeds фиксируются. Основная метрика — raw summed causal log-likelihood preference для правильного предложения при заданном BOS; EOS не оценивается, нормализации по длине нет. Это стандартное для BLiMP teacher-forced scoring, а не свободная генерация ответа.

Чтобы не принять эффект длины за языковое улучшение, критерий подтверждения заранее требует положительной нижней границы парного 95% стратифицированного bootstrap-интервала **и на полном test, и на его подмножестве одинаковой токенной длины**. Это заранее фиксированное пересечение критериев. Дополнительно сообщаются регрессии по всем разделам, exact paired sensitivity и macro accuracy. Пять коротких жадных продолжений — только иллюстрации.

Все гипотезы формулируются по diagnostic. Для каждой — три заранее записанных величины коэффициента; затем три зарегистрированные комбинации. Максимум 12 полных оценок validation, каждая начинается с оригинала. Критерий выбора — точность validation, меньше регрессий, меньше изменённых значений, меньшая L2-норма. Нет output-temperature-only кандидата; каждый должен реально менять минимум 10 000 независимых значений. Градиенты, обучение, оптимизатор, регрессия и случайный поиск содержательных кандидатов не используются.

Три случайных контроля после выбора имеют ту же фактическую ненулевую маску и общую L2-норму с допуском float32. Seeds не отбираются. Проверяются нулевая правка, откат, shapes/dtype/ключи, buffers и ties, конечность значений, сохранность вне маски и воспроизводимость после загрузки в новом процессе. Диагностические hooks читают активации и удаляются; в итоговом инференсе их нет.

## Совместимость checkpoint

Одна техническая попытка остановилась до validation из-за перенесённого имени `model.embed_tokens` в проверке ties. Исправлена только проверка на `transformer.wte`; scoring, данные, seeds и бюджет сохранены. Baseline повторён, открытые прогнозы совпали точно, хеш закрытого файла прогнозов тоже совпал без просмотра исходов. Старый оценщик, протокол и запись сбоя находятся в results/technical_failures, поправка протокола — в protocol_amendments.json. Эта попытка не является дополнительной оценкой validation; отдельно сохранены ровно 12 полных оценок.

Источник сохранён Transformers 4.28. Его фиксированные attention-mask buffers проверяются против конструктора текущей официальной GPT-Neo и исключаются только как непостоянные buffers при строгой загрузке параметров. Отсутствующее второе имя связанного readout восстанавливается из исходного embedding, без случайной инициализации. Официальный from_pretrained служит независимой проверкой совпадения тензоров и прогнозов. Эти предшествующие baseline операции совместимости не выдаются за улучшение весов.

На case-insensitive macOS исходные README.md и readme.md сохранены под разными локальными именами с remote_paths и проверкой Git blob SHA, чтобы не перезаписать друг друга. Это файловая адаптация, не изменение модели.

## Ограничения и источники

Один checkpoint, один редактор и ограниченный бюджет не устанавливают общий эффект на LLM. TinyStories — домен простых историй, BLiMP содержит и редкую лексику; отсутствие пересечений с исходным обучением не проверено. Шаблоны и словарь BLiMP сохраняют зависимость между примерами. Интервалы относятся к выбранной правке и тестовым примерам, не к повторным предобучениям. Большое число изменённых значений не гарантирует улучшения, а короткие продолжения не доказывают повышение связности.

Модель: Eldan, Li (2023), *TinyStories: How Small Can Language Models Be and Still Speak Coherent English?* https://arxiv.org/abs/2305.07759 . Checkpoint https://huggingface.co/roneneldan/TinyStories-1M , revision в sources.json. Явная лицензия модели в зафиксированной карточке/дереве не найдена; разрешение распространять исходные веса не утверждается. Публичный пакет использует скрипт скачивания и edit_spec вместо перепаковки чужого checkpoint.
