# Прямое редактирование весов малых трансформеров

Три локальных эксперимента: можно ли улучшить готовую нейросеть, изменив часть её весов без дообучения? Проект содержит код применения правок, бенчмарки, протоколы, предсказания и результаты сравнения исходных и изменённых моделей.

**На основных итоговых тестах устойчивого улучшения не получено.** Некоторые ошибки удалось исправить, но возникли новые. Все проверенные варианты сохранены, включая неудачные.

Модели предобучены их авторами. В этих экспериментах градиенты и оптимизаторы не использовались; архитектура и токенизаторы сохранялись. Гипотезы правок и код подготовлены при участии языкового агента Codex. Эксперименты выполнены на CPU, без Colab и платных API.

## Эксперименты и результаты

В таблице показаны выбранные по валидации правки и результаты на основных отложенных тестах.

| Модель | Изменено независимых весов | Примеров в тесте | Точность до → после |
|---|---:|---:|---:|
| Трансформер сложения, 1 644 параметра | 52 | 5 000 | 98,86% → 98,86% |
| Glimmer-1-Base, 11 856 параметров | 16 | 4 928 | 53,186% → 53,105% |
| TinyStories-1M, 3 745 984 параметра | 66 048 | 4 917 | 66,057% → 66,036% |

- **Сложение:** масштабированы запросы одной головы внимания и строка токена завершения; аналитически изменено финальное смещение. На основном тесте исправлено 9 ошибок и добавлено 9 новых. На стрессовом тесте точность выросла с 98,30 до 98,75%, а при полном переборе пар чисел 0–99 снизилась с 99,97 до 99,93%.
- **Glimmer:** 16 весов финальной нормализации умножены на 1,25. На тесте появились 4 новые ошибки без исправлений. Изменение вероятностей не означает улучшения свободной генерации.
- **TinyStories:** выходные проекции внимания умножены на 0,9, проекции запросов — на 0,8 во всех восьми блоках. Исправлена 181 ошибка, добавлено 182 новых. Проверялись и более широкие правки — до 197 632 значений.

Большое число изменённых весов не означает столько же независимо подобранных коэффициентов: здесь применяются групповые преобразования. Число параметров TinyStories указано с учётом эмбеддингов; название «1M» не равно фактическому общему числу параметров.

## Какие данные использованы

**CarryBench-10** — собственный синтетический бенчмарк сложения неотрицательных целых чисел до десяти разрядов. Один пример содержит два слагаемых и эталонную сумму. Проверяются случайные примеры, случаи с переносами и все 10 000 упорядоченных пар чисел от 0 до 99. Правильным считается весь сгенерированный ответ, включая специальный токен завершения EOS.

**BLiMP** — бенчмарк грамматических минимальных пар английского языка. Один пример содержит два предложения: грамматически правильное и неправильное. Проверяется, присваивает ли модель правильному варианту большую суммарную логарифмическую вероятность. Начало задаётся служебным токеном BOS; EOS в оценку не включается, нормирования по длине нет. Это проверка предпочтения между предложениями при заданном контексте, а не свободная генерация ответа.

Для Glimmer выбраны восемь разделов BLiMP, для TinyStories — восемь других. **TinyStories здесь является названием модели; тестовые задания взяты из BLiMP.** Поэтому проценты двух языковых моделей нельзя использовать как их прямой рейтинг.

Для каждой модели выделены отдельные наборы:

| Назначение | Размер | Как использовался |
|---|---:|---|
| Диагностика | 1 024 примера | Анализ ошибок и формулирование гипотез правок |
| Валидация | 2 048 примеров | Сравнение кандидатов и выбор итоговой правки |
| Итоговый тест | См. таблицу результатов | Проверка после фиксации выбранной правки |

Для арифметической модели примерами являются задачи на сложение, для языковых — пары предложений. Разбиение BLiMP на эти наборы выполнено в рамках проекта.

## Как устроен эксперимент

Для каждой модели выполнено 12 полных валидационных оценок: отдельные преобразования с несколькими коэффициентами и их предусмотренные протоколом композиции. Итоговые результаты открывались после фиксации выбранных весов, спецификации и кода; после этого новая правка по тем же тестам не подбиралась. Разделение доступа к тестовым исходам было организационным.

Сохраняются исправления и регрессии на одних и тех же примерах. В отчётах приведены парные 95%-е бутстрэп-интервалы и три случайных контроля с той же маской и нормой изменения. Проверяются сохранение и загрузка, откат, связанные веса и неизменность значений вне объявленной маски.

- `REPORT.md` — результаты и их интерпретация;
- `sources.json` — источники, зафиксированные версии и контрольные суммы;
- `protocol.json`, `freeze.json` — условия эксперимента и фиксация артефактов;
- `edit_spec.json` — точная спецификация выбранной правки;
- `results/attempts.json` — журнал всех кандидатов;
- `results/final/comparisons.json` и `.csv` — итоговые сравнения;
- `data/`, `hypotheses/`, `tests/` — наборы заданий, гипотезы и проверки.

## Быстрый запуск: восстановление готовой правки

Пример для арифметической модели после чистого клонирования репозитория. Нужен **Python 3.12**; команды рассчитаны на macOS/Linux. Зависимости и исходная модель загружаются из Интернета, инференс выполняется локально.

```bash
cd weight_programming
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python fetch_sources.py
.venv/bin/python restore_selected.py

# Исходная модель
.venv/bin/python inference.py --checkpoint upstream/checkpoints/best.pt --a 47 --b 38

# Та же задача после зафиксированной правки
.venv/bin/python inference.py --checkpoint checkpoints/selected_reconstructed.pt --a 47 --b 38
```

`restore_selected.py` восстанавливает уже выбранную правку по спецификации и проверяет контрольную сумму тензоров. Повторный подбор кандидатов и обучение не запускаются. Скрипт защищён от перезаписи существующего выходного файла; при необходимости укажите новый путь через `--out`.

Для Glimmer и TinyStories используется тот же порядок: установить зависимости соответствующей папки, выполнить `fetch_sources.py`, затем `restore_selected.py`. Инференс запускается через `language_model.py`, например из папки Glimmer:

```bash
.venv/bin/python language_model.py 'The cat'
.venv/bin/python language_model.py 'The cat' --checkpoint checkpoints/selected_reconstructed.pt
```

Полный повтор эксперимента с подготовкой данных, диагностикой и новым подбором правок описан в README каждой модели. Его выполняют в отдельной чистой папке с исходниками и зависимостями, без прежних `results`, `protocol.json` и `freeze.json`. В репозитории уже сохранены результаты завершённых запусков.

## Ограничения

Исследованы три конкретных checkpoint с ограниченным бюджетом поиска. Отсутствие пересечений с первоначальным обучением моделей не установлено. Предложения BLiMP сохраняют общие шаблоны, а суммарная вероятность зависит от длины токенизации. В TinyStories дополнительно проверено подмножество одинаковой длины: общий прирост там также не получен.

Бутстрэп-интервалы относятся к выбранной правке и тестовым примерам, а не к независимым повторным обучениям моделей. Для четырёх изменившихся исходов Glimmer точная парная проверка даёт p = 0,125; устойчивое ухудшение не установлено. Результаты не доказывают ни универсальную эффективность, ни невозможность прямого редактирования весов.
