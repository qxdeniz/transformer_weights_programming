# CarryBench-10 / прямое программирование весов

Локальный эксперимент на CPU, без Colab и внешних платных API. Исходная модель — готовый decoder-only трансформер на 1 644 параметра, один блок, d_model=8, две головы, d_ff=12. Источник, commit и SHA-256 — в `sources.json`. Веса автора сохранены без изменений в `upstream/checkpoints/best.pt` и `checkpoints/base.pt`.

Методология и ограничения для статьи: **BENCHMARK.md**. Реальные итоговые измерения после завершения эксперимента: **REPORT.md**, таблица **results/final/comparisons.csv**, все попытки **results/attempts.json**. Отсутствие улучшения также фиксируется. Общая математическая компетентность и дробное умножение здесь не измеряются.

После появления `freeze.json` редактирование закрыто. Повторный `report` только пересчитывает сравнение сохранённых прогнозов; новых правок не делает.

## Чистое воспроизведение

Создайте отдельную папку, скопируйте собственные `.py`, `tests/`, `sources.json` и этот README. Не копируйте прежние protocol/results/checkpoints/freeze. Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python fetch_sources.py
.venv/bin/python run_experiment.py --stage prepare
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python run_experiment.py --stage baseline
.venv/bin/python diagnose.py
.venv/bin/python propose_edits.py
.venv/bin/python run_experiment.py --stage finalize
.venv/bin/python make_paper_artifacts.py
```

`propose_edits.py` воспроизводит ровно 12 заранее ограниченных содержательных кандидатов, а не запускает обучение или общий оптимизатор. Для одной явной гипотезы интерфейс:

```bash
.venv/bin/python run_experiment.py --stage edit --edit-spec hypotheses/edit_01.json --max-candidates 12
.venv/bin/python run_experiment.py --stage report
```

Не запускайте одновременно ручные `--stage edit` и полный `propose_edits.py`: журнал бюджета общий. При воспроизведении логики выбора правок формулы фиксированы в `propose_edits.py`; исходное решение агента на основании диагностических примеров описано в `hypotheses/preregistered_hypotheses.json`.

Для построения PDF/SVG рисунков дополнительно установите `matplotlib`. Основной эксперимент требует только torch и numpy; версии и фактическое железо фиксируются в `environment.txt`. Первоначальный запуск здесь использует отдельный venv Python 3.12 с доступными установленными пакетами, не изменяя системные установки. Обучение модели в нашем эксперименте не выполняется.

## Разделение данных

Открытые результаты — `results/baseline/{diagnostic,validation}.jsonl`. Финальные baseline-прогнозы сначала пишутся отдельными процессами в `sealed_final/baseline`; они не выводятся в консоль и не используются при подборе. `finalize` сначала фиксирует хеши выбранных весов, edit_spec, evaluator и protocol, затем выполняет финальные сравнения и открывает исходные результаты. Это организационное, а не технически непроницаемое разделение.

Каждая строка прогноза содержит id, операнды, точный эталон, входные и выходные токены, исходное декодирование, strict EM, digit-only EM, формат и число токенов. Главная метрика учитывает EOS; метрика README автора его не учитывает. Правильная числовая сумма при отсутствующем EOS остаётся ошибкой основной метрики.

Файлы `data/` содержат 20 072 фиксированных примера. Даты, seeds, смеси, критерии, бюджет, контрольные seeds и SHA-256 находятся в `protocol.json`. Числа с ведущими нулями используют неизменный десятиразрядный входной формат автора.

## Артефакты и происхождение

`apply_edit.py` принимает только базовые тензоры и декларативную спецификацию изменения. Правильные ответы ему не передаются. `inference.py` получает пары чисел и вызывает неизменную исходную жадную генерацию; эталоны доступны только оценщику. Диагностические hooks только читают активации в отдельном `diagnose.py` и удаляются; финальные процессы их не устанавливают.

В публичном дереве исходного репозитория не найдена явная лицензия кода или весов. Доступность на GitHub не трактуется как разрешение распространять checkpoint. Папка здесь — частный рабочий экземпляр; для публичных материалов используются собственный код, результаты и загрузчик оригинала с проверкой хешей. Публикация весов или чужого кода этим проектом не выполняется.

После финального сравнения нельзя подбирать новую правку по тем же финальным ошибкам и называть её независимым подтверждением. Для продолжения нужен новый протокол с новыми случайными тестами. Диапазон 0…99 уже просмотрен и новым от смены seed не становится.
